# 0.5.2 访问调度回归记录

2026-10-09。本报告来自可控假时钟和模拟平台接口，使用项目实际后台调度、传输、准入及读取代码，不代表真实学习通网络耗时或完成速度。

| 场景                                           | 实际测试断言                                                     |
| ---------------------------------------------- | ---------------------------------------------------------------- |
| 三次即时访问，含原生导航及 offscreen 读取      | 派发开始于 0 / 1000 / 2000ms，首次无等待。                       |
| 第一次访问后已耗时 700ms                       | 后续实际访问只补等 300ms，于 1000ms 派发。                       |
| 第一次访问后已耗时 1500ms                      | 后续访问于 1500ms 立即派发。                                     |
| 700ms 时命中缓存                               | 不发送准入申请，也不推进派发时钟；后续访问仍在 1000ms 开始。     |
| 同账号、用途、完整 URL、fresh 的两个进行中读取 | 真实 fetch 一次；首个调用者取消时第二个仍获得结果。              |
| 全部订阅者取消 / 迟到放行                      | 不再派发；取消且未派发的请求不影响后续时间。                     |
| 连续三次 fresh 完成核验                        | 都读取服务器，0 / 1000 / 2000ms，没有额外固定睡眠。              |
| 已加载 num 0 的三分页章节                      | num 0 不重复点击；真实打开 num 1/2，读取绑定 frame 的快照。      |
| 有效快照的媒体启动                             | 仅一次卡片导航，一次本地 HTML 读取，启动前额外 HTML fetch 为 0。 |
| 快照文档被替换                                 | 仅一次最新网络补读，不再次打开卡片。                             |
| 同卡片下一个资源 / 用户暂停后恢复              | 有效拥有的卡片复用，恢复后重新导航一次。                         |
| 验证码、9010、429、账号变化或运行暂停          | 后续派发与缓存返回被阻断；无自动重试。                           |
| 界面等待                                       | 仅显示实际未到期的间隔；放行、缓存、取消及结束清除等待。         |

版本 0.5.1 的访问常量为 5000ms；0.5.2 为 1000ms。仅在即时响应、连续真实访问的受控条件下，三次访问的最小开始时间从 0 / 5000 / 10000ms 改为 0 / 1000 / 2000ms。旧流程还受页面耗时和缓存影响，不能据此宣称每项都会节省固定 10 秒。

## 验证方式

本页记录 0.5.2 的受控调度回归，不是当前版本的现场平台验收，也不承诺实际网络耗时。旧版本地 JSON 报告和平台截图不随公开源码发布。当前版本的可重复检查见 [发布验收说明](acceptance.md)。

```powershell
npm.cmd ci
npm.cmd run release
npm.cmd audit --omit=dev
```

如需补充真实 Edge 检查，应分别记录扩展主动派发次数与浏览器页面子资源请求数、首次及后续读取时间、缓存和页面来源，以及实际等待显示。模型速度、视频时长和阅读器条件不属于本页的间隔优化测量。
